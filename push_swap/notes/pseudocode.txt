How to read this file:
  - On the LEFT is the pseudo code (what the computer does).
  - After the  ->  is the "explain it like I'm a dummy" part.
  - It is NOT C. You translate it to C yourselves, line by line.
    That way the code is really ours and we can explain it at defense.

Words we use everywhere:
  node    = one box in the list. It has a value and an arrow (next)
            to the box below it.
  top     = the first node. The stack pointer (a or b) points to it.
  NULL    = "nothing here". The last node's next is NULL.
  *a      = "the top of stack a" (in C you pass t_node **a so the
            function can CHANGE which node is the top).


====================================================================
STEP 0 - THE BIG STRUCT (push_swap.h)
====================================================================

t_node:
    value               -> the number the user typed, e.g. -300
    rank                -> its place in sorted order, 0 = smallest (step 1c)
    next                -> arrow to the node below, NULL if it's the last

t_ps:  (one bag that holds EVERYTHING, so we never need globals)
    a                   -> top of stack a
    b                   -> top of stack b
    size                -> how many numbers the user gave
    strategy            -> which algorithm: SIMPLE, MEDIUM, COMPLEX, ADAPTIVE
    bench               -> 1 if the user wrote --bench, else 0
    disorder            -> the number from step 3 (0.0 .. 1.0)
    count[11]           -> how many times each op was used:
                           count[SA], count[SB] ... count[RRR]
                           (bench prints these at the end)

Why a bag: every function gets  t_ps *ps  and can reach both stacks
and the counters. The subject forbids global variables, so this is the
"legal" way to share things.


====================================================================
STEP 1 - PARSING
====================================================================

--------------------------------------------------------------
ps_atoi(text, out)       returns 1 = OK, 0 = ERROR
--------------------------------------------------------------
Why change it: today ps_atoi returns 0 for errors. But 0 is ALSO a
real number. So the answer "0" means two things -> bug.
New idea: the RETURN only says OK/ERROR, and the number goes into *out.

 1  i = 0                     -> i is our finger, it points at a letter
                                 of the text. Start at the first letter.
 2  sign = 1                  -> we assume the number is positive.
 3  result = 0   (type long)  -> we build the number here. "long" is
                                 bigger than int, so we can see when it
                                 goes past INT_MAX before it breaks.
 4  if text[i] is '+' or '-': -> is there a sign in front?
 5      if it is '-':
 6          sign = -1         -> remember it's negative
 7      i = i + 1             -> move the finger past the sign
 8  if text[i] is NOT a digit:-> after the sign there MUST be a digit.
 9      return 0 (ERROR)         This catches "", "-", "+", "abc".
10  while text[i] is a digit:
11      result = result * 10 + (text[i] - '0')
                              -> "push" the digit in from the right.
                                 Example "42": 0*10+4 = 4, then 4*10+2 = 42.
                                 text[i] - '0' turns the letter '4'
                                 into the number 4 (ASCII trick).
12      if sign * result > INT_MAX  or  sign * result < INT_MIN:
13          return 0 (ERROR)  -> too big for an int. We check INSIDE the
                                 loop so "long" never overflows either.
14      i = i + 1             -> next letter
15  if text[i] is not '\0':   -> we stopped, but NOT at the end of the
16      return 0 (ERROR)         text. So something like "12abc".
17  *out = sign * result      -> put the finished number in the box
                                 the caller gave us
18  return 1 (OK)

Test:  "0" -> OK 0   "-0" -> OK 0   "12abc" -> ERROR   "" -> ERROR
       "2147483647" -> OK   "2147483648" -> ERROR   "-2147483648" -> OK


--------------------------------------------------------------
parse_args(ps, argc, argv)
--------------------------------------------------------------
 1  i = 1                     -> argv[0] is "./push_swap", skip it
 2  while i < argc:           -> look at every word the user typed
 3      if argv[i] is "--bench":
 4          ps->bench = 1     -> remember it, do NOT put it in the stack
 5      else if argv[i] is "--simple" / "--medium" / "--complex" / "--adaptive":
 6          if a strategy was already chosen:
 7              ft_error(ps)  -> two strategy flags = we refuse
 8          ps->strategy = that one
 9      else:                 -> it should be a number
10          if ps_atoi(argv[i], &num) == 0:
11              ft_error(ps)  -> not a valid int -> Error, free, exit
12          node = ft_node_new(num)
13          if node is NULL:  -> malloc failed
14              ft_error(ps)
15          ft_nodeadd_back(&ps->a, node)
                              -> add at the BOTTOM, so the first number
                                 typed ends up on TOP (subject rule)
16          ps->size = ps->size + 1
17      i = i + 1
18  if ps->strategy was never set:
19      ps->strategy = ADAPTIVE  -> the default, says the subject

Note: the strcmp check must be EXACT. Use ft_strncmp(argv[i], "--bench", 8)
      - the 8 includes the '\0', so "--benchXYZ" does not match.


--------------------------------------------------------------
ft_error(ps)                                     (error.c)
--------------------------------------------------------------
 1  ft_nodeclear(&ps->a)      -> free every node of a (no leaks even
                                 when we fail!)
 2  ft_nodeclear(&ps->b)      -> same for b
 3  write(2, "Error\n", 6)    -> 2 = stderr. 6 = number of letters
                                 E,r,r,o,r,\n
 4  exit(1)                   -> stop the whole program right now


--------------------------------------------------------------
set_ranks(ps)   + duplicate check                (src/stack/ranks.c)
--------------------------------------------------------------
Why ranks: numbers can be -500, 7, 99999. Ugly to divide into chunks
or look at bits. Ranks turn them into 0, 1, 2 ... n-1. Same order,
nice small numbers.
   values: 42  -7  1000  3
   ranks:   2   0     3  1      (-7 is smallest -> 0)

 1  copy = malloc(ps->size ints)  -> an array, as big as the stack
 2  if copy is NULL: ft_error(ps)
 3  node = ps->a ;  i = 0
 4  while node:                   -> walk down the stack
 5      copy[i] = node->value     -> write each value in the array
 6      node = node->next ; i++
 7  insertion_sort(copy, ps->size)
                                  -> YOUR function from practice/!
                                     now copy is sorted small -> big
 8  i = 0
 9  while i < ps->size - 1:       -> look at each pair of neighbours
10      if copy[i] == copy[i + 1]:
11          free(copy) ; ft_error(ps)
                                  -> after sorting, two equal numbers
                                     are ALWAYS next to each other.
                                     That's the duplicate check!
12      i++
13  node = ps->a
14  while node:                   -> for every node...
15      node->rank = position of node->value inside copy
                                  -> search copy from 0 until
                                     copy[j] == node->value, rank = j
16      node = node->next
17  free(copy)                    -> we don't need the array anymore


====================================================================
STEP 2 - OPERATIONS
====================================================================
Draw boxes and arrows on paper for each one. Seriously - it's the
fastest way to understand pointers.

--------------------------------------------------------------
swap(s)         top two change places        (sa / sb)
--------------------------------------------------------------
Before:  s -> [1] -> [2] -> [3] -> NULL
After:   s -> [2] -> [1] -> [3] -> NULL

 1  if *s is NULL or (*s)->next is NULL:
 2      return                -> 0 or 1 node: nothing to swap
 3  first = *s                -> hold [1]
 4  second = first->next      -> hold [2]
 5  first->next = second->next-> [1] now points to [3]
 6  second->next = first      -> [2] now points to [1]
 7  *s = second               -> the top is now [2]
(This is the same as your sa, just with names that say what they are.)

--------------------------------------------------------------
push(from, to)   top of "from" goes on top of "to"   (pa / pb)
--------------------------------------------------------------
Before:  from -> [1] -> [2]        to -> [9]
After:   from -> [2]               to -> [1] -> [9]

 1  if *from is NULL:
 2      return                -> empty: nothing to push (today it crashes!)
 3  node = *from              -> hold [1]
 4  *from = node->next        -> "from" now starts at [2]
 5  node->next = *to          -> [1] points to the old top of "to" ([9])
 6  *to = node                -> [1] is the new top of "to"

pb = push(&a, &b)     pa = push(&b, &a)     <- watch the ORDER

--------------------------------------------------------------
rotate(s)       top goes to the bottom       (ra / rb)
--------------------------------------------------------------
Before:  s -> [1] -> [2] -> [3] -> NULL
After:   s -> [2] -> [3] -> [1] -> NULL

 1  if *s is NULL or (*s)->next is NULL: return
 2  first = *s                -> hold [1]
 3  *s = first->next          -> top is now [2]
 4  first->next = NULL        -> [1] will be the last, so it points to nothing
 5  last = ft_nodelast(*s)    -> find [3]
 6  last->next = first        -> hang [1] under [3]

--------------------------------------------------------------
reverse_rotate(s)   bottom goes to the top   (rra / rrb)
--------------------------------------------------------------
Before:  s -> [1] -> [2] -> [3] -> NULL
After:   s -> [3] -> [1] -> [2] -> NULL

 1  if *s is NULL or (*s)->next is NULL: return
 2  before_last = *s
 3  while before_last->next->next is not NULL:
 4      before_last = before_last->next
                              -> stop at the node BEFORE the last one
                                 (here [2]). We need it because it
                                 becomes the new last.
 5  last = before_last->next  -> hold [3]
 6  before_last->next = NULL  -> [2] is now the end of the list
 7  last->next = *s           -> [3] points to the old top [1]
 8  *s = last                 -> [3] is the new top

Your current rrotate never finds "before_last", that's why it does a
normal rotate instead.

--------------------------------------------------------------
The 11 wrappers (what the subject calls sa, pb, rra ...)
--------------------------------------------------------------
sa(ps):
 1  swap(&ps->a)              -> do the move
 2  write(1, "sa\n", 3)       -> print the name (stdout = fd 1)
 3  ps->count[SA]++           -> +1 for the bench

ss(ps):
 1  swap(&ps->a) ; swap(&ps->b)
 2  write(1, "ss\n", 3)       -> ONE line, not "sa" + "sb"
 3  ps->count[SS]++           -> ss counts as ONE operation

Same pattern for sb pa pb ra rb rr rra rrb rrr.
"rra" has 4 letters with \n -> write(1, "rra\n", 4).


====================================================================
STEP 3 - DISORDER + SORTED CHECK
====================================================================

--------------------------------------------------------------
compute_disorder(a)
--------------------------------------------------------------
Idea: take every PAIR of numbers (one above, one below). If the one
above is bigger -> it's in the wrong order -> a "mistake".
disorder = mistakes / all pairs.
Example 2 1 3 4: pairs (2,1)X (2,3) (2,4) (1,3) (1,4) (3,4)
                 1 mistake / 6 pairs = 0.1666 -> 16.67%

 1  mistakes = 0 ; pairs = 0
 2  i = a                     -> i = the "upper" number of the pair
 3  while i is not NULL:
 4      j = i->next           -> j = every number BELOW i
 5      while j is not NULL:
 6          pairs++
 7          if i->value > j->value:
 8              mistakes++    -> bigger number is above -> wrong order
 9          j = j->next
10      i = i->next
11  if pairs == 0: return 0   -> 0 or 1 number: never divide by zero!
12  return (double)mistakes / pairs
                              -> (double) so 1/6 gives 0.1666 and not 0
                                 (int / int in C throws away the decimals)

--------------------------------------------------------------
is_sorted(a)
--------------------------------------------------------------
 1  while a and a->next:
 2      if a->value > a->next->value: return 0   -> found a wrong pair
 3      a = a->next
 4  return 1                  -> walked to the end, all good

In main: if is_sorted -> free everything and exit, print NOTHING.


====================================================================
STEP 4 - SIMPLE STRATEGY  O(n^2)   (your selection_sort idea)
====================================================================

Helpers first:
--------------------------------------------------------------
stack_size(s)       -> count nodes: walk and do count++ until NULL
min_position(s)     -> walk with an index; remember the index where
                       the smallest rank is. Return that index.
                       (top = position 0)
--------------------------------------------------------------

--------------------------------------------------------------
sort_three(ps)      3 numbers in max 2 operations
--------------------------------------------------------------
Call the ranks top / middle / bottom.
 1  if top is the biggest:    ra(ps)   -> biggest goes to the bottom
 2  else if middle is the biggest: rra(ps) -> bottom comes up, biggest
                                            is now at the bottom
 3  if top > middle (after step 1/2):  sa(ps)
Check all 6 orders on paper: 123 132 213 231 312 321. Each one works.

--------------------------------------------------------------
simple_sort(ps)
--------------------------------------------------------------
Selection sort: "find the smallest, put it away, repeat".
In push_swap "put it away" = pb. Stack b fills up small -> big,
so b's top is always the biggest-so-far. pa brings them back in order.

 1  while stack_size(a) > 3:
 2      pos = min_position(a)
 3      size = stack_size(a)
 4      if pos <= size / 2:   -> min is in the TOP half
 5          do ra(ps) pos times      -> rotate it up
 6      else:                 -> min is in the BOTTOM half
 7          do rra(ps) (size - pos) times
                              -> going "backwards" is shorter
 8      pb(ps)                -> smallest is on top -> put it in b
 9  sort_three(ps)            -> the last 3 are easy
10  while b is not NULL:
11      pa(ps)                -> bring them back one by one.
                                 We pushed the smallest FIRST, so it is
                                 at the BOTTOM of b. The top of b is the
                                 biggest of b. Every number in b is
                                 smaller than the 3 left in a.
                                 So: pa puts the biggest of b on top of a,
                                 then the next smaller one above it, ...
                                 and the smallest comes last = on top.
                                 Try it on paper with 5 4 1 3 2.
Why O(n^2): for each of the n numbers we rotate up to n/2 times.


====================================================================
STEP 5 - MEDIUM STRATEGY  O(n * sqrt(n))   (your chunk_sort idea)
====================================================================
Idea: cut the ranks into chunks of size ~sqrt(n).
  100 numbers -> sqrt = 10 -> chunks: 0-9, 10-19, ... 90-99
Push chunk 1 to b, then chunk 2, ... Then pull back from b, always
the biggest first.

 1  n = stack_size(a)
 2  chunk = 1
 3  while chunk * chunk < n: chunk++   -> chunk = sqrt(n) without math.h
 4  low = 0
 5  while a is not NULL:
 6      high = low + chunk            -> this chunk = ranks low..high-1
 7      pushed = 0
 8      while pushed < chunk and a is not NULL:
 9          if low <= a->rank < high:
10              pb(ps) ; pushed++     -> belongs to this chunk -> to b
11          else:
12              ra(ps)                -> not yet, skip it (goes to bottom)
13      low = high                    -> next chunk
                                      (careful: the last chunk can be
                                       smaller, that's why line 8 also
                                       checks "a is not NULL")
14  while b is not NULL:              -> phase 2: bring back
15      pos = max_position(b) ; size = stack_size(b)
16      if pos <= size / 2: rb(ps) pos times
17      else:               rrb(ps) (size - pos) times
18      pa(ps)                        -> biggest left goes on top of a.
                                         Next one smaller goes above it...
                                         so a ends up sorted.
Why O(n*sqrt(n)): sqrt(n) chunks, each one walks a at most once (n ra).
And in phase 2 the max is always close (its chunk is near the top).

Easy upgrade later (fewer ops): in line 10, if the rank is in the
LOWER half of the chunk, also do rb(ps). Keeps b more organized.

--------------------------------------------------------------
MEDIUM - FULL EXAMPLE BY HAND  (the one from medium_strat_notes.txt)
--------------------------------------------------------------
Input: 7 2 9 1 5 8 3 6 4      (top is on the LEFT)
n = 9  ->  chunk = 3  (3*3 = 9)  ->  3 chunks
   chunk 1 = the 3 smallest  = values 1 2 3   (ranks 0 1 2)
   chunk 2 = the next 3      = values 4 5 6   (ranks 3 4 5)
   chunk 3 = the 3 biggest   = values 7 8 9   (ranks 6 7 8)

PHASE 1 - move everything to b, chunk by chunk.
Rule: look at the top of a. In my chunk? -> pb.  Not mine? -> ra.

 chunk 1 (want 1 2 3)
   op    A (top left)          B (top left)
         7 2 9 1 5 8 3 6 4     -
   ra    2 9 1 5 8 3 6 4 7     -            7 is not mine, skip
   pb    9 1 5 8 3 6 4 7       2            2 is mine
   ra    1 5 8 3 6 4 7 9       2
   pb    5 8 3 6 4 7 9         1 2
   ra    8 3 6 4 7 9 5         1 2
   ra    3 6 4 7 9 5 8         1 2
   pb    6 4 7 9 5 8           3 1 2        got 3 -> chunk done

 chunk 2 (want 4 5 6)
   pb    4 7 9 5 8             6 3 1 2
   pb    7 9 5 8               4 6 3 1 2
   ra    9 5 8 7               4 6 3 1 2
   ra    5 8 7 9               4 6 3 1 2
   pb    8 7 9                 5 4 6 3 1 2

 chunk 3 (want 7 8 9) - everything left is mine
   pb    7 9                   8 5 4 6 3 1 2
   pb    9                     7 8 5 4 6 3 1 2
   pb    -                     9 7 8 5 4 6 3 1 2

 Look at b now:  [9 7 8] [5 4 6] [3 1 2]
 It is NOT sorted, but it is "sorted by blocks": big block on top,
 small block at the bottom. That is the whole trick. The biggest
 number is never far from the top.

PHASE 2 - bring back to a, ALWAYS the biggest of b first.
Rule: where is the max of b? Top half -> rb until it is on top.
      Bottom half -> rrb. Then pa.

   op        A                 B
             -                 9 7 8 5 4 6 3 1 2
   pa        9                 7 8 5 4 6 3 1 2     9 was already on top
   rb        9                 8 5 4 6 3 1 2 7     8 was at position 1
   pa        8 9               5 4 6 3 1 2 7
   rrb       8 9               7 5 4 6 3 1 2       7 was at the bottom!
   pa        7 8 9             5 4 6 3 1 2            1 rrb, not 6 rb
   rb rb     7 8 9             6 3 1 2 5 4
   pa        6 7 8 9           3 1 2 5 4
   rrb rrb   6 7 8 9           5 4 3 1 2
   pa        5 6 7 8 9         4 3 1 2
   pa        4 5 6 7 8 9       3 1 2
   pa        3 4 5 6 7 8 9     1 2
   rb        3 4 5 6 7 8 9     2 1
   pa        2 3 4 5 6 7 8 9   1
   pa        1 2 3 4 5 6 7 8 9 -            SORTED

 Phase 1 = 15 ops, phase 2 = 16 ops, total 31.

Why is this faster than simple (step 4)?
 Simple looks for the min in the WHOLE stack every time -> far away.
 Here the max is always inside the top block (or just rotated to the
 bottom) -> only about sqrt(n) steps away, never n steps.
 n numbers * about sqrt(n) steps each = n * sqrt(n).
   100 numbers: simple ~ 100*100/4 = 2500 ops, medium ~ 100*10 = 1000.


====================================================================
STEP 6 - COMPLEX STRATEGY  O(n log n)   (radix on bits)
====================================================================
Every rank is a number in binary:  5 = 101,  2 = 010,  6 = 110
Idea: sort by the LAST bit, then the next bit, ... like your
radix_sort.c sorts by the last digit, then the next digit.
But with only 2 "buckets": bit 0 -> goes to b, bit 1 -> stays in a.

 1  n = stack_size(a)
 2  max_bits = 0
 3  while ((n - 1) >> max_bits) != 0: max_bits++
                              -> how many bits does the biggest rank
                                 need? 99 -> 7 bits. 499 -> 9 bits.
                                 ">> k" = shift right k times = throw
                                 away the last k bits.
 4  bit = 0
 5  while bit < max_bits:
 6      i = 0
 7      while i < n:          -> look at EVERY number exactly once
 8          if ((a->rank >> bit) & 1) == 0:
                              -> ">> bit" moves the bit we want to the
                                 end, "& 1" keeps only that last bit.
                                 Example rank 6 = 110, bit 1:
                                 110 >> 1 = 11, 11 & 1 = 1
 9              pb(ps)        -> bit is 0 -> to b
10          else:
11              ra(ps)        -> bit is 1 -> stays in a, goes to bottom
12          i++
13      while b is not NULL:
14          pa(ps)            -> bring all the 0s back on top
15      bit++
Why O(n log n): log(n) bits, each bit costs about n + n/2 ops.
500 numbers: 9 bits * ~750 = ~6700 ops (pass is < 12000).

--------------------------------------------------------------
COMPLEX - FIRST, WHAT IS A "BIT"?
--------------------------------------------------------------
We write numbers with digits 0-9. The computer writes them with only
0 and 1. Each 0/1 is a "bit".
   rank 0 = 00      rank 1 = 01      rank 2 = 10      rank 3 = 11
The RIGHT bit is "bit 0", the next one to the left is "bit 1".

How to read one bit in C:   (rank >> bit) & 1
   rank = 2 = 10
   bit 0:  10 >> 0 = 10,  10 & 1 = 0      -> the right bit is 0
   bit 1:  10 >> 1 =  1,   1 & 1 = 1      -> the left bit is 1
   ">>" slides the number to the right, "& 1" looks only at the last bit.

This is why we NEED ranks (step 1c): bits of -5 or 2147483647 are a
mess. Ranks are 0 .. n-1, small and never negative.

--------------------------------------------------------------
COMPLEX - FULL EXAMPLE BY HAND
--------------------------------------------------------------
Input: 40 -5 12 7
Ranks:  3  0  2  1        (-5 smallest = 0, then 7 = 1, 12 = 2, 40 = 3)
In bits: 11 00 10 01
n = 4 -> biggest rank is 3 = 11 -> 2 bits -> we do 2 rounds.
Below we write the RANKS (that is what the code looks at).

ROUND 1 - look at bit 0 (the RIGHT bit).   0 -> pb    1 -> ra
   op    A (top left)     B         why
         3 0 2 1          -
   ra    0 2 1 3          -         3 = 1[1]  right bit is 1 -> stay
   pb    2 1 3            0         0 = 0[0]  right bit is 0 -> to b
   pb    1 3              2 0       2 = 1[0]  right bit is 0 -> to b
   ra    3 1              2 0       1 = 0[1]  right bit is 1 -> stay
   -- we looked at all 4 numbers, now bring b back --
   pa    2 3 1            0
   pa    0 2 3 1          -
 Result: 0 2 | 3 1   -> first the ones ending in 0, then the ones
                        ending in 1. Sorted by the right bit only.

ROUND 2 - look at bit 1 (the LEFT bit).
   op    A                B         why
         0 2 3 1          -
   pb    2 3 1            0         0 = [0]0  left bit is 0 -> to b
   ra    3 1 2            0         2 = [1]0  left bit is 1 -> stay
   ra    1 2 3            0         3 = [1]1  left bit is 1 -> stay
   pb    2 3              1 0       1 = [0]1  left bit is 0 -> to b
   pa    1 2 3            0
   pa    0 1 2 3          -         SORTED  (= -5 7 12 40)
 12 operations.

Why does it work? (the question they WILL ask at defense)
 Round 1 puts things in order by the right bit.
 Round 2 sorts by the left bit BUT keeps the order from round 1 for
 numbers that have the same left bit. Look at round 2: 2 and 3 both
 have left bit 1. 2 was before 3 after round 1, and it is still
 before 3 at the end. Nobody "jumps over" - that is called a STABLE
 sort, and radix only works because each round is stable.
 (pb reverses the order in b, pa reverses it again -> order is kept.)

Why line 7 says "while i < n" and not "while a is not NULL":
 The numbers we ra go to the bottom of a and would come back to the
 top again. We must look at each number exactly ONCE per round, so
 we count n looks and stop.

Why O(n log n):
 Rounds = number of bits = log2(n).  100 numbers -> 7 rounds,
 500 numbers -> 9 rounds. Double the numbers = only 1 more round.
 Each round = n looks (pb or ra) + the pa's.
 n * log(n). It always costs the same, sorted or messy input -
 that is why adaptive only uses it when disorder is HIGH.

MEDIUM vs COMPLEX - when is which better?
   n      medium (n*sqrt n)    complex (n*log n)
   100    ~1000                ~1100         about the same
   500    ~11000               ~6700         complex wins
 For small n they are close. For big n complex wins clearly.
